---------------------------------------------------------------
THE GOLDEN RULE
---------------------------------------------------------------

Every feature lives in ONE of these places:

  apps/api/src/         — backend routes, business logic, Meta API calls
  apps/webhook/src/     — processes incoming WhatsApp events from Meta
  apps/web/app/         — Next.js pages and UI components
  packages/database/    — Prisma schema (only touch if adding DB columns)

When adding a feature, decide which of these it touches, make
the code changes locally, then follow the deploy steps below.

---------------------------------------------------------------
STEP-BY-STEP: HOW TO DEPLOY A CODE CHANGE (detailed)
---------------------------------------------------------------

1. MAKE YOUR CHANGES LOCALLY
   Edit files in your C:\Users\DURSAU\Documents\Claude\Projects\WHATSAPP folder.
   Ask Claude to help write the code — give it this folder as context.

2. PUSH TO GITHUB AND PULL ON SERVER
   Local:  git add -A && git commit -m "feat: description" && git push
   Server: cd /home/silent/whatsapp-saas/WHATSAPP && git pull

3. REBUILD ONLY WHAT CHANGED
   You don't need to rebuild everything — only the affected app(s):

   If you changed apps/api:
     cd /home/silent/whatsapp-saas/WHATSAPP
     pnpm --filter @whatsapp-saas/api build
     pm2 restart wa-api

   If you changed apps/webhook:
     pnpm --filter @whatsapp-saas/webhook build
     pm2 restart wa-webhook

   If you changed apps/web:
     pnpm --filter @whatsapp-saas/web build
     pm2 restart wa-web

   If you changed the Prisma schema (packages/database/prisma/schema.prisma):
     pnpm --filter @whatsapp-saas/database build
     pnpm --filter @whatsapp-saas/database exec prisma db push
     # Then rebuild all apps that use the database:
     pnpm --filter @whatsapp-saas/api build && pm2 restart wa-api
     pnpm --filter @whatsapp-saas/webhook build && pm2 restart wa-webhook

   If you changed multiple apps at once:
     pnpm build
     pm2 restart all

4. VERIFY
     pm2 status                        — all 3 should show "online"
     pm2 logs wa-api --lines 10 --nostream
     curl https://api.whatsapi.buzz/health


---------------------------------------------------------------
COMMON FEATURE ADDITIONS — WHERE TO LOOK
---------------------------------------------------------------

ADD A NEW API ENDPOINT
  File: apps/api/src/routes/SOMETHING.ts
  Then register it in: apps/api/src/index.ts
  Pattern: copy any existing route file as a template.
  Rebuild: api only.

ADD A NEW DASHBOARD PAGE
  File: apps/web/app/(dashboard)/dashboard/PAGENAME/page.tsx
  The (dashboard) folder automatically wraps it in the sidebar layout.
  Rebuild: web only.

ADD A NEW DATABASE TABLE/COLUMN
  File: packages/database/prisma/schema.prisma
  Add your model or field, then run:
    pnpm --filter @whatsapp-saas/database exec prisma db push
    pnpm --filter @whatsapp-saas/database build
  Then rebuild api and webhook.

CHANGE HOW INCOMING WHATSAPP MESSAGES ARE HANDLED
  Files: apps/webhook/src/handlers/messages.ts
         apps/webhook/src/handlers/account-events.ts
  Rebuild: webhook only.

ADD A NEW META API CALL (send template, get media, etc.)
  File: apps/api/src/lib/meta.ts
  Add a new exported function. Then call it from a route.
  Rebuild: api only.


---------------------------------------------------------------
ENVIRONMENT VARIABLES
---------------------------------------------------------------

If a feature needs a new env variable, add it to:
  apps/api/.env        — for the API service
  apps/webhook/.env    — for the webhook receiver
  apps/web/.env.local  — for the frontend (use NEXT_PUBLIC_ prefix for browser-visible vars)

After adding env vars:
  pm2 restart wa-api --update-env
  pm2 restart wa-webhook --update-env
  pm2 restart wa-web --update-env

---------------------------------------------------------------
KEY THINGS THAT WENT WRONG DURING FIRST DEPLOY (DON'T REPEAT)
---------------------------------------------------------------

1. DATABASE_URL must use postgres.PROJECT_REF as username:
   WRONG:   postgresql://postgres:PASSWORD@...
   CORRECT: postgresql://postgres.dhbmbscmsazbmsdrcpma:PASSWORD@...

2. DATABASE_URL must have &pgbouncer=true for Supabase transaction pooler (port 6543).

3. apps/api/tsconfig.json must have "strict": false and "declaration": false
   (otherwise TypeScript errors on Express Router types).

4. packages/database must be built FIRST before building api or webhook:
   pnpm --filter @whatsapp-saas/database build

5. ecosystem.config.js uses node_modules/next/dist/bin/next (not the .bin symlink)
   and dist paths are dist/apps/api/src/index.js (not dist/index.js).

6. After ANY nginx config change: sudo nginx -t && sudo systemctl reload nginx

7. WABA ID in credentials must exactly match the entry.id Meta sends in webhooks.
   If messages aren't arriving, check: pm2 logs wa-webhook --lines 20 --nostream
   and look for "Unknown WABA ID: XXXXXX" to get the real ID.
